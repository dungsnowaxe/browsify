# Domain docs

## Layout: single-context

- `GLOSSARY.md` at the repo root contains shared domain vocabulary.
- `docs/adr/` contains architectural decision records.

## Before exploring

Read the glossary and ADRs relevant to the work.
If absent, proceed silently; domain-modeling creates them lazily
when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR, naming
the ADR and explaining why the decision merits reopening.

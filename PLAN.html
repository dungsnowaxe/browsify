Browsify — Revised Technical Specification & Rust Architecture Plan

A standalone, ultra-lean Rust successor to Finicky for macOS (com.lavenxsnow.browsify) with a platform-agnostic core. Engineered for < 6 MB RSS memory, sub-5 µs declarative URL routing, < 1 µs cached browser profile resolution, 0 MB idle UI overhead, zero telemetry by default, and 100% drop-in compatibility with Finicky v3/v4 configurations.

Target RAM: ~4.5–5.7 MB RSS (550 KB dirty anon) Hot Path: 2.35 µs (Native) / 42.5 µs (Hybrid QuickJS) Bundle ID: com.lavenxsnow.browsify (http, https, browsify, finicky) Config UI: Token-Authenticated 127.0.0.1 HTTP/SSE (0 MB idle) Domain Docs: GLOSSARY.md · ADR-0001 · ADR-0002

Launch Plan The concrete execution plan produced by resolving a Browser Target and its Profile Selector into final launch arguments, target URL, instance-spawning behavior, and window activation policy. Launch config, open command

ADR-0001: Compile-Time Hybrid Lowering with Ephemeral QuickJS

docs/adr/0001-hybrid-lowering-with-ephemeral-quickjs.md — Evaluates .js/.ts configs in rquickjs, lowers declarative rules and explicit finicky.* helper markers to native Rust matchers/transforms, and drops the QuickJS VM completely when 0 dynamic JS callbacks remain. Mixed configs run as an ordered hybrid pipeline where static steps execute in Rust and OS queries are bound as lazy Rust host callbacks.

ADR-0002: On-Demand Loopback HTTP UI Server Instead of WKWebView

docs/adr/0002-on-demand-loopback-ui-server.md — Serves apps/browsify-ui on demand over an ephemeral, token-authenticated 127.0.0.1:0 HTTP + SSE server in the user's browser and shuts down ~30s after the last UI tab closes, eliminating the 40–80+ MB permanent RSS cost of an in-process WKWebView.

3. Existing Rust & Native Alternatives — How Browsify Improves on Grinch & Finch

Source-Level Analysis of Grinch (Rust) & Finch (Swift)

1. Ephemeral QuickJS 5.1 MB vs 15.5 MB

  • Grinch links macOS JavaScriptCore and holds a live Retained<JSContext> for the lifetime of the process (~15.5 MB RSS).
  • Browsify: Uses rquickjs (~550 KB dirty RAM) and drops the JS runtime completely when all rules lower to native Rust (~4.5 MB RSS).

2. Smarter Profile Cache mtime + Typed Serde

  • Grinch parses Chrome's entire Local State into a serde_json::Value tree, ignores file mtime, and caches transient read failures permanently.
  • Browsify: Deserializes only profile.info_cache.* via typed serde structs (659 µs cold) and auto-invalidates via (mtime_ns, size) stat checks (0.87 µs warm).

3. True Finicky v3/v4 Compatibility Zero Breakage

  • Grinch alters bare string semantics, rejects .finicky.ts, fails on finicky.getPowerInfo(), and drops rules.json & short-URL expansion.
  • Browsify: Preserves 100% of Finicky v3 & v4 semantics, supports .js/.ts/.toml/rules.json, and ships browsify migrate.

4. Profile Window Focus & Spaces Fix Issues #501 & #550

  • Spawning a transient helper browser instance with --profile-directory drops macOS window focus when the helper exits.
  • Browsify: Uses direct NSWorkspace launching and invokes NSRunningApplication::activateWithOptions on the primary browser process after handoff.

5. Visual Rules UI with 0 MB Idle RAM Best of Both Worlds

  • Finicky keeps a heavy WKWebView in memory forever; Grinch and Finch deleted the GUI entirely.
  • Browsify: Serves the Svelte 5 UI (apps/browsify-ui) over an ephemeral token-authenticated 127.0.0.1:0 server with 0 MB idle RAM.

6. Cross-Platform Core & CI Testability Linux + macOS

  • Grinch and Finch couple their config engine to macOS JavaScriptCore, preventing Linux compilation/testing.
  • Browsify: packages/browsify-core and packages/browsify-js compile and pass 100% of tests on both Linux and macOS.

Safe Marker-Based Lowering & Ordered Hybrid Pipeline (packages/browsify-js)

1. No Regex Guessing on fn.toString()

  • Arbitrary JS functions are never regex-sniffed via Function.prototype.toString(), preventing miscompilation of conditional closures.
  • Only declarative values (wildcard strings, RegExp instances, arrays, static browser objects) and explicit helper markers (finicky.matchHostnames, finicky.matchDomains, finicky.stripParams, finicky.matchOpener, finicky.forceHttps, finicky.replaceHost) lower to native browsify-core steps.

2. Interleaved Native + QuickJS Pipeline

  • Rewrites compile to Vec<HybridRewrite> (Native(CompiledRewrite) or Js(usize)) and handlers compile to Vec<HybridHandler> (Native(CompiledHandler) or Js(usize)).
  • During URL resolution, (current_url, original_url, opener) flows through each step in order: static steps execute in native Rust (~1 µs), and QuickJS is entered only when a Js(index) step is reached.
  • QuickJS URL parsing delegates to a Rust url::Url host helper for 100% identical WHATWG URL behavior (IPv6, punycode, relative paths).
  • When 0 Js(index) steps exist, rquickjs::Runtime and Context are dropped immediately after config load.

macOS AppKit Daemon & Native System Integration (apps/browsify/src/macos.rs)

1. Event Loop & URL Interception

  • Runs as an LSUIElement agent when invoked with no CLI subcommand or --window.
  • Handles kInternetEventClass / kAEGetURL AppleEvents, application:openFile:, NSUserActivityTypeBrowsingWeb (Handoff), and ASWebAuthenticationSession SSO callbacks.
  • Enforces single-instance execution via non-blocking flock (/tmp/browsify-startup-<uid>/startup.lock) + duplicate bundle-ID termination.

2. Lazy OS Queries & Short URLs

  • Lazy Accessibility: Queries AXUIElementCopyAttributeValue for opener.windowTitle only when uses_window_title == true on the active config.
  • Lazy Host Callbacks: getModifierKeys() (CoreGraphics), getPowerInfo() (IOKit), getSystemInfo(), and isAppRunning() execute on-demand when invoked by JS.
  • Short-URL Expansion: Follows up to 3 plain-HTTP redirects in-process (750 ms per-hop timeout, zero TLS binary bloat) with a 256-entry LRU cache; HTTPS shorteners pass through unresolved until the native macOS NSURLSession expander lands.

3. Status Bar, Hot-Reload & Focus Fix

  • Menu Bar: Mode/Status header, Rules & URL Tester…, 10-item Recent URLs submenu, Set as Default Browser, Edit Config…, Reload Config, and Quit Browsify.
  • File Watcher: Watches Primary Config and rules.json via kqueue/polling to hot-reload rules and update the error badge automatically.
  • Focus Handoff (#501/#550): Direct NSWorkspace launch + NSRunningApplication::activateWithOptions after helper exit.

6. Configuration Precedence, Telemetry Policy & Migration CLI

Deterministic Precedence Across Primary Config & UI Rules File

Evaluation & Fallback Precedence

  1. Primary Config Rewrites (config.toml or .{browsify,finicky}.{js,ts}) mutate the URL in order.
  2. Primary Config Handlers are evaluated first.
  3. UI Rules File Handlers (rules.json) are evaluated next as fallback handlers.
  4. Default Browser & Options Inheritance: If the Primary Config omits default_browser or any options field, Browsify inherits the setting from rules.json (and the UI displays a lock/override badge when a setting is explicitly defined by the Primary Config).

Zero Telemetry & Update Check Policy

  • Module Formats: ES Module export default { ... }, CommonJS module.exports = { ... }, and TypeScript type annotations (import type ..., url: URL, satisfies FinickyConfig).
  • URL Objects: Full WHATWG URL + URLSearchParams + FinickyURL with legacy v3 getters (url.urlString, url.url returning {protocol, username, password, host, port, pathname, search, hash}, and url.opener).
  • finicky.* Global Utilities: finicky.matchHostnames(...), finicky.matchDomains(...), finicky.getModifierKeys(), finicky.getSystemInfo(), finicky.getPowerInfo(), finicky.isAppRunning(id), and finicky.notify(title, subtitle).
  • Browser Extension Protocol: Handles both finicky://open/<base64> and browsify://open/<base64> so existing Chrome/Firefox Finicky extensions work without modification.
  • Legacy Finicky's custom API_HOST telemetry/update endpoint is completely removed.
  • check_for_updates defaults to false so Browsify makes zero background network requests unless explicitly opted in.
  • When check_for_updates = true, Browsify queries GitHub Releases (https://api.github.com/repos/snowaxe/browsify/releases/latest) at most once per 24 hours, caching the result in ~/Library/Caches/Browsify/last_update_check.json.

7. Token-Authenticated On-Demand Localhost UI & Rebranding

0 MB Idle RAM · CSRF-Protected Loopback Server · MIT Attribution

1. Session Token & Origin Security

When launched via menu bar or browsify ui, the server binds to 127.0.0.1:0, generates a random 128-bit session token, and opens http://127.0.0.1:<port>/?token=<hex>. All /api/rpc and /api/events requests verify both the session token header/query and loopback Host/Origin.

2. SSE Log Stream & 30s Auto-Stop

The UI connects to GET /api/events (Server-Sent Events) to receive real-time log entries for LogViewer.svelte and config reload notifications. When all SSE clients disconnect (browser tab closed), a 30-second grace timer stops the listener and frees all UI buffers back to 0 MB.

3. Browsify Rebrand & MIT Attribution

apps/browsify-ui and apps/browser-addon are branded as Browsify (showing Native vs. Hybrid QuickJS status in the UI and using browsify://open/ in the extension while accepting finicky://open/). LICENSE, About.svelte, and README.md preserve full MIT copyright notice and credit John Sterling (@johnste) and @uetchy.

8. Phased Implementation Plan

Execution Sequence

Phase 1: Core & Hybrid Engine Refinement (browsify-core, browsify-js)

  • Remove sunsetted Arc Space fields (space, arc_space, list_arc_spaces) from browsify-core and browsify-js.
  • Add profile: "container:<Name>" parsing in ProfileResolver so rules.json and UI rules can target Firefox Containers.
  • Add 256-entry LRU cache + bounded in-process HTTP redirect resolver in shorturl.rs (native macOS NSURLSession HTTPS expander tracked as a follow-up).
  • Replace fn.toString() regex sniffing in browsify-js with safe helper markers (matchHostnames, matchDomains, stripParams, matchOpener, forceHttps, replaceHost).
  • Implement ordered interleaved Vec<HybridRewrite> & Vec<HybridHandler> pipeline preserving options.originalUrl, Rust-backed WHATWG URL parsing, lazy host callbacks, and uses_window_title detection.
  • Default check_for_updates to false and support inheriting unset defaultBrowser/options from rules.json.

Phase 2: macOS AppKit Daemon & Native Launcher (apps/browsify)

  • Implement objc2 NSApplication daemon in macos.rs: kAEGetURL, application:openFile:, Handoff, ASWebAuthenticationSession, NSStatusBar menu (with 10-item Recent URLs, Set as Default Browser, Edit Config…, Reload Config, error badge), lazy AXUIElement windowTitle, and IOKit power info.
  • Implement direct NSWorkspace launching and post-handoff NSRunningApplication activation in launcher.rs.
  • Add automatic file watching hot-reload for Primary Config and rules.json, plus GitHub Releases update checker (when opted in).

Phase 3: Secure On-Demand UI Server & Browsify UI / Addon

  • Upgrade ui_server.rs with per-launch session token + Origin validation, SSE log streaming (/api/events), 30s idle auto-shutdown after tab disconnect, bundle-relative asset loading, and installed-browser filtering.
  • Update apps/browsify-ui and apps/browser-addon with Browsify branding, SSE log consumer, Primary Config override indicators, and upstream MIT credits to John Sterling & @uetchy.

Phase 4: Legacy Cleanup, Packaging & Verification

  • Move bundle assets (Info.plist with com.lavenxsnow.browsify, icons, browsify.d.ts, finicky.d.ts) to apps/browsify/assets/ and remove legacy apps/finicky/ and packages/config-api/.
  • Update LICENSE, scripts/build.sh, scripts/test.sh, and .github/workflows/ for the Rust workspace and Browsify.app bundle.
  • Run full Rust unit/integration test suite and UI typecheck/build verification.
